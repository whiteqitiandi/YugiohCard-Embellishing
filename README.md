# 秘藏決鬥圖鑑（Arcana Archive）

純單機、個人欣賞用途的遊戲王卡片圖鑑與藝術加工雛型。目前完成：

- 本機 SQLite 圖鑑、跨語言搜尋、密碼萬用字元、卡圖與規則版本切換。
- 卡片圖鑑可在「詳細檢視」與高密度「網格目錄」間切換；目錄支援圖鑑順序、名稱、攻擊力、守備力、等級／階級／LINK、首次發行日及卡片種類排序，並可用方向鍵選擇鄰近卡片、Enter 開啟詳細檢視。每頁最多列數可由目錄或「設定」選單調整，也可切換為全部卡片單頁模式。
- 網格目錄採純縮圖與右側大卡圖配置；效果文字預設收合，可展開查看完整文字與鐘擺效果。
- 網格工具列與「設定」選單可切換「顯示不同卡圖版本」；關閉時每個卡名只佔一格，開啟時每張不同插圖都是可用方向鍵選取的獨立目錄項目。
- 網格目錄可拖曳框選本頁多張卡片，再按「設為冷門卡片」或「設為非冷門卡片」批次儲存；支援 Ctrl／⌘ 點選加減、Shift 連選、本頁全選與 Esc 清除。兩種操作都會直接設定指定狀態，不會反向切換原本已符合的卡片。方向鍵維持大圖預覽，空白鍵可加減目前卡片；切換頁面、排序或搜尋結果會清除舊選取。
- 全部卡片單頁模式採列虛擬化，只建立可見範圍及少量前後緩衝列；搜尋、排序、方向鍵與框選仍以完整結果集運作，避免一次掛載全部縮圖及卡圖解析器。大量設定冷門狀態則合併為一次 IPC 與單一 SQLite 交易，避免逐張往返主程序。
- 獨立的「資料更新中心」：YGOPRODeck 提供卡片結構／發行日／英文名稱，百鴿（YGOCDB）提供中文文字與日文名稱，再以 OpenCC 轉台灣正體；YGOResources 依 Konami 資料庫 ID 補齊並驗證不同卡圖版本。
- OCG 更新只要求中文卡名與效果文完整，不因缺少日文／英文而失敗；TCG 維持限定卡要求中／英、跨區卡要求中／英／日的規則。
- 可指定 OCG／TCG 的單一發行月份，或續傳更新「截至指定年月（含）的全部卡片」；來源各自節流並保存發行涵蓋進度。
- 獨立的進階篩選視窗：類別、細分、屬性與種族同組多選固定採聯集，只有效果支援納入／排除及聯集／交集。
- 可手動把卡片標記為本機冷門卡，並在篩選與常用條件中設定顯示全部、隱藏冷門或只顯示冷門。
- 仿 Duel Links Chronicle Card 的分層加工實驗室（表面、範圍、邊框、卡名、印章）。
- Electron 原生功能選單與可持久化的介面文字大小設定。
- 卡片創作、牌組工房的導覽與資料邊界已預留，尚未實作。

## 啟動

可直接使用 [`輔助批次檔`](./輔助批次檔) 內的批次檔：

1. 首次執行 `install.bat`。
2. 日常執行 `run.bat`。它會優先使用本專案 Electron；若 binary 尚未快取，可只讀借用 `C:\War3ModelElectron` 的既有 Electron 執行檔。
3. 驗證正式建置執行 `rebuild.bat`。
4. 清除可重建檔案前，先執行 `pure.bat --dry-run` 預覽。

也可在 PowerShell 手動執行：

```powershell
npm install
npm run dev
```

## 更新卡片資料

由左側進入「資料更新中心」，選擇發行地區、年份、月份與更新方式：

- 「指定單一月份」只處理該月。
- 「截至指定年月的全部卡片」會從上次未完成的發行月份／月內位置接續；達到任一來源的單批流量上限後，冷卻 30 秒便自動開始下一批，直到指定範圍完成。
- 更新中心會分別顯示「已掃描至」與「完整涵蓋至」，以及待補張數。進度條代表掃描月份及月內位置，100% 不代表沒有缺漏；完整涵蓋日期不會跨過尚未補齊的缺口。
- 遇到必要語系缺漏時，完整卡片仍會匯入，殘缺卡片連同已取得的資料快照另存 SQLite 缺漏清單；保存後直接處理下一張、下一個月份，不會因語系缺漏自動暫停，也不會在後續正常更新反覆掃描相同缺口。
- 「待補資料清單」可查看卡片密碼、發行月份、缺少的欄位（中文卡名／效果文、英文／日文卡名）、來源、首次發現／最近檢查時間與檢查次數。可按「只重試缺漏卡片」補查所選地區截至指定年月的待補資料，不必重新下載整個月份的卡片結構資料。
- 補查會以開始時的缺漏清單為範圍，每張每輪僅嘗試一次，仍依 100 張／次、最多 5 次／500 張及批間冷卻 30 秒的限制分批執行；成功後移出待補清單，仍缺資料的保留到日後，不會在同一輪無限重試。
- 可隨時「暫停更新／繼續更新」或「取消作業」。取消會停止後續作業，不刪除已匯入資料；每 100 張以內保存續傳位置。暫停後接續或取消後重新開始仍遵守冷卻時間。
- 作業由主程序管理，切換頁面或重新載入介面不會中斷，也不會重複啟動。關閉程式會停止更新；下次開啟後可手動從已保存的位置接續。

YGOPRODeck API v7 負責卡片結構、OCG／TCG 各自發行日、英文名稱與基礎圖片清單；百鴿 API 負責中文卡名、中文效果文與日文名稱，中文並以 OpenCC 轉為台灣正體（屬機器轉換，非官方繁中校訂）；YGOResources 的卡圖索引則依 Konami 資料庫 ID 補齊各插圖版本。同一插圖的多語圖片不會被重複列為不同版本，代表圖片依繁體中文／中文、日文、英文的順序選用。選擇 OCG 更新時，只要中文卡名與效果文完整即可匯入，即使該卡也在 TCG 發行，仍不要求日文／英文；已有的其他語系名稱不會因來源本次缺漏而清空。選擇 TCG 更新時維持原規則：TCG 限定卡要求中／英，同時在兩區發行的卡要求中／英／日名稱。未達到語系條件的卡片不會冒充完整資料放入圖鑑，而是保留於待補清單，不影響後續掃描。卡圖不會在更新時批次下載，而是在實際查看時下載一次並存入本機媒體分片。

月份掃描完成後，更新流程會比較 YGOPRODeck 資料庫版本並分頁核對完整卡表，補進無法由發行月份查詢取得的卡片；既有但缺少來源欄位的卡片會再依八位卡號定向回查。完整卡表會覆核結構資料及卡圖清單，卡圖網址依卡片去重，來源版本、稽核時間與筆數則寫入 SQLite，避免只依月份篩選造成長期缺卡。需要手動強制重建時可執行：

```powershell
npm run catalog:reconcile -- --database="$env:APPDATA\ArcanaArchive\catalog.sqlite"
```

本程式對各來源採獨立的保守流量政策（不是宣稱來源官方的額度）：YGOPRODeck 月份更新每頁 100 張、至少間隔 1 秒、每輪最多 40 次請求；百鴿每次請求 100 張、至少間隔 2 秒、每輪最多 5 次請求／500 張；YGOResources 完整卡圖索引每次稽核只下載一次。每輪之間額外冷卻至少 30 秒。語系缺漏不會中斷作業；只有來源拒絕／連線失敗、無法安全保存資料或續傳位置無法推進等錯誤才會自動暫停並顯示原因。介面中的日期均指卡片發行日期，不是軟體執行更新的時間。來源規格請見 [YGOPRODeck API Guide](https://ygoprodeck.com/api-guide/)、[百鴿 API 文件](https://ygocdb.com/api) 與 [YGOResources artwork index](https://github.com/yugioh-artworks/artworks-index)。

## 卡片資料庫位置

- Git 追蹤的乾淨基準資料庫：`data/catalog.sqlite`。它包含卡片文字、來源欄位及卡圖網址清單，不包含個人的冷門卡標記；第一次啟動且尚無使用者資料庫時會複製為可寫入版本。
- 實際執行中的可寫入資料庫：`C:\Users\<使用者>\AppData\Roaming\ArcanaArchive\catalog.sqlite`（也就是 `%APPDATA%\ArcanaArchive\catalog.sqlite`）。程式更新、待補清單及冷門卡標記都保存在這裡，升級程式不會覆蓋既有檔案。
- 實際卡圖影像仍按需下載到同一個使用者資料目錄下的媒體分片，不加入 Git；因此儲存庫不會因數萬張圖片而膨脹，SQLite 基準本身已足以免除每次重抓卡表。

離線流程驗證可執行 `npm test`，以模擬來源和時鐘檢查分批上限、自動接續、暫停／取消及錯誤保護，不會大量呼叫真實來源。

網格框選與批次冷門標記的測試也包含在 `npm test`；可單獨執行 `npm run test:directory`，檢查框選範圍、連選、設定／取消冷門標記、重複操作與部分儲存失敗處理。

完整研究、資料來源選擇與階段規劃請見 [`Doc/開發計畫.md`](./Doc/開發計畫.md)。
